# 📜 Changelog

All notable changes to the **Location Tracking & 5-Case Journey Analysis App** will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

---

## [2.0.0+6] - 2026-07-25 *(Major Feature Release)*

### 🚀 Added
- **Tactile `SwipeActionButton`**: Replaced standard tap button with an interactive swipe-to-start / swipe-to-stop slider control (`SwipeActionButton`) featuring directional progress glow and velocity threshold validation.
- **Fluid Adaptive Font System**: Implemented dynamic text scaling (`textScaler` builder) in `MaterialApp` based on a 390px width baseline. Fonts scale fluidly across 320px compact phones, standard smartphones, and 600px+ tablets.
- **`v2.0.0` Version Branding**: Added explicit version indicator subtitle on `SplashScreen`.
- **Standalone `AdaptiveFont` Utility**: Added `lib/utils/adaptive_font.dart` for fine-grained per-widget responsive text sizing.

### 🐛 Fixed
- **SQLite Database Schema Migration (Version 5)**: Bumped SQLite database version from `4` to `5` and added auto-migration rules for `user_id`, `user_name`, `device_id`, and `device_model` columns. Fixed `SQLITE_ERROR: table location_logs has no column named user_id` crash on existing installed devices.
- **Background Isolate Flutter Binding**: Added `WidgetsFlutterBinding.ensureInitialized()` inside `startCallback()` and `MyForegroundTaskHandler.onStart()` to ensure SQLite and location plugins function reliably inside secondary Flutter background isolates.
- **Stationary Logging Threshold**: Reduced `UserActivity.still` location capture interval from 300 seconds to 30 seconds for responsive feedback during desktop/indoor testing.

## [1.3.0] - 2026-07-25 *(User Identity & Anti-Tampering Security)*

### 🚀 Added
- **Sales Rep & Device Profile Mapping**:
  - Integrated `device_info_plus` to automatically detect device specs (`device_id`, `device_model`, `os_version`).
  - Added corporate identity fields (`user_id`, `user_name`, `user_email`) stored in `SharedPreferences`.
  - Enriched all raw GPS fixes and journey analysis reports with user & device details.
- **Mandatory Profile Enforcement**: Location tracking sessions cannot be started without saved user details. Prompts for profile setup if missing, then uses persistent storage seamlessly without repeated prompts.
- **Anti-Tampering Protection**:
  - **Mock GPS Rejection**: Detects and discards location fixes generated by Fake/Mock GPS apps (`position.isMocked`).
  - **Security Audit Logging**: Created `audit_logs` SQLite table to record immutable security events (`MOCK_LOCATION_REJECTED`, `GPS_HARDWARE_DISABLED`, `GPS_HARDWARE_ENABLED`).
- **Open-Source Repository Security**: Excluded `api_config.dart`, `google-services.json`, and `GoogleService-Info.plist` via `.gitignore`. Added template placeholder files (`api_config.template.dart`, `google-services.json.template`) for safe public GitHub deployment.

### 🐛 Fixed
- **Chronological Journey Numbering**: Updated journey order calculation (`journeys.length - index`) in `JourneyHistoryScreen` so card badges accurately reflect true creation order (`Journey #1` for 1st travel run).

## [1.2.0] - 2026-07-24 *(Multi-Journey Isolation & Design Refresh)*

### 🚀 Added
- **Multi-Journey Session Isolation**: Persisted `active_journey_id` in `SharedPreferences` to prevent cross-journey data mixing if the OS kills or restarts the Flutter UI.
- **App Launcher Icon Refresh**: Replaced app launcher icon with Option 2 (Minimalist Radar & Map Marker) across all density folders (`mipmap-mdpi` through `mipmap-xxxhdpi`).
- **Status Bar Notification Icon**: Updated `ic_notification.png` to a flat white pin outline on 100% transparent background for Android status bar standards.
- **OpenStreetMap Engine**: Integrated `flutter_map` with OpenStreetMap tile servers (`https://tile.openstreetmap.org/{z}/{x}/{y}.png`) for 100% free route map rendering.

## [1.1.0] - 2026-07-24 *(5-Case Gap Engine & Cloud Firestore)*

### 🚀 Added
- **5-Case Gap Reconstruction Engine**:
  - *Case 1*: Normal GPS tracking ($\le 2$ min gap).
  - *Case 2*: Stationary stop ($> 2$ min gap & $< 150$m movement).
  - *Case 3*: Missing travel gap fill via Google Routes REST API.
  - *Case 4*: GPS drift detection.
  - *Case 5*: Fallback handling.
- **Periodic Cloud Sync**: Automated 5-minute periodic upload queue to Cloud Firestore (`sales_gps_logs`) with 5s connection timeout handling.
